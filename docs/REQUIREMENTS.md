# 需求与验收对应

本表区分现有实现、已验证证据和剩余验证，完整目标仍包含最初的玩法与技术约束。构建和运行结果分别以 [BUILD](BUILD.md)、[Paper 验收](PAPER-ACCEPTANCE.md) 及其带哈希的证据文件为准。

| 原始要求 | 实现与证据 | 当前边界 |
| --- | --- | --- |
| 分析并复用 StarCore、森罗物语 | [StarCore 对接](STARCORE.md)、[森罗对接](SENLUO.md)，固定两个上游提交；`StarCoreGateway` 与公开服务 | 国家、战争、货币和国库由 StarCore 管理，不通过其数据库扣款 |
| 统一战略物资、国家仓库与前线 | 六类 `ResourceType`；物品映射、完整 ItemStack 批次和 SQL 仓库；六类 Paper 采购运输闭环 | 原版与 Cookery 成品进入真实托管；每周期消耗完整物品 |
| 军队需求、消耗、短缺和后勤状态 | `ArmySupplyRules`、`CampaignRules`、`computeArmySupply`、`SupplyStatus` 与军队 GUI | 战力临时有界；失守、超距暂停消费；不追扣停服周期 |
| 原生 SupplyLine、路线、道路、敌区、截断恢复、备选 | [路线](ROUTING.md)，异步图计算、完整区块扫描、交付重新规划 | 原生线仍以 StarCore 的战争、容量和损毁状态为准 |
| 玩家商队、货物、订单、护送、风险、费用、保险、失败结算 | SQL 实物预留与承运人、独立护送队、批次固定风险、StarCore 运费和 [收入险](INSURANCE.md) | 逻辑不依赖实体持续加载；NPC 表现属于原需求可选设计；护送无独立奖金 |
| 协定、进出口、供需价格、采购、禁运、收益、关税、战时管制、区域差异 | [市场](MARKET.md) 与 `openSale`；按仓库隔离的供需参考价；StarCore 方向协定与禁运、TARIFF；战时出口配置 | 合同锁价；实际货物不能同时计入 StarCore 抽象资源库存 |
| 农业、厨师、运输和侦察参与 | 小麦/面团/馒头上游配方流程、Cookery 身份品质验证、玩家供货运输、亲临道路侦察 | 食物生产由森罗原玩法完成；StarSupply 不生成免费军粮 |
| Tavern 情报交换、商人集结与真实自定义物品 | [酒馆](TAVERNS.md)、可选真实酒品认证、国家情报板及开放合同 | 情报有时效、按国家隔离；上游没有自动酒馆注册表，集合点由授权玩家登记 |
| 持续作战、短缺、围城、道路失守、冬季、经济负担、公平恢复 | 有界战力与真实物资成本；前线控制/距离、道路风险、季节/围城临时需求、采购运费保费 | 围城依赖 [上游财政初始化补丁](upstream/README.md)；第三方战斗扩展聚合可能影响倍率 |
| 物资映射、运输、军需公开 API、事件、GUI/地图接口 | `SupplyApi`、`TavernApi`、`InsuranceApi`；可取消操作事件、经济结算事件、周期消耗事件；`routeNetwork` | 地图渲染由接口接入，未强制捆绑特定地图插件；通知不是可靠消息队列 |
| 独立 SQL、唯一结算、跨库恢复、真实库存、权限 | [事务](TRANSACTIONS.md)，主库 v8、酒馆 v1、保险 v2；StarCore 收据与唯一经济阶段；实体线程权限与操作事件 | 没有外部幂等回执的结果保持复核，不能凭当前余额自动重试或退款 |
| 异步路线、Folia 调度兼容 | 玩家使用实体调度器，后台 SQL/路线使用限流工作线程，战役采样在全局服务器任务 | 完整 Folia 组合尚未完成：固定 StarCore 使用传统调度器且无 Folia 声明，当前验收目标是 Paper |
| 重启、断线、并发、重复交付测试与可构建交付 | 69 项当前 StarSupply 测试、分阶段 Paper 证据；源码、配置、映射示例、构建脚本、JAR 与审查包 | 每个运行记录只证明对应哈希和步骤；故障恢复与可选依赖需按验收记录逐项核验 |

第一阶段所需的四类资源、国家仓库、军需、基础路线、玩家订单、真实交货和经济结算、Cookery 示例、战争效果、GUI 与持久化均有代码实现；当前提供六类资源。完整目标是否完成还取决于上表未验证的组合与验收分支，不能由构建通过或单条闭环代替。
