# 商队承运收入险

StarSupply 的承运收入险由发单国家承保，只对本国承运者开放。保险保护运输遭袭时损失的运费收入。货物仍使用原有库存批次：遭袭失败时退回起点，保险不会再生成物品、赔偿货值或增加前线补给。未投保的中立玩家仍可按照普通运输规则承运。

在起点仓库、领取运输单之前，使用 `/supply insurance <运输UUID>` 查看报价，使用 `/supply insure <运输UUID>` 投保。承保成功后运输绑定该承运者，再使用 `/supply accept <运输UUID>` 出发。保险报价、状态和经济阶段可通过 `InsuranceApi` 查询。

赔额固定为合同运费的 80%，向下取到两位小数。保费按下面公式向上取到两位小数，并受最低保费限制：

```text
赔额 = 运费 × 0.80
保费 = max(最低保费, 赔额 × (投保时路线风险 + 附加费率))
```

默认附加费率为 10%，最低保费为 1.00，可通过 `insurance.loading-rate` 和 `insurance.minimum-premium` 配置。零风险路线无需投保。赔额、保费、承运者、采购批次和风险上限在签约时锁定。线路风险变化后不能凭旧保险改走更危险的路线；需退保或使路线重新符合承保风险上限。

## 资金与货物状态

激活保险之前，StarSupply 通过 StarCore `NationSpendingService` 按唯一保险 UUID 预扣完整赔额，作为真实的国家准备金。随后通过 StarCore 内部经济扣除承运者保费，再将保费存入国家国库。三个步骤都确认后保险才成为 `ACTIVE`，开放承运操作。

成功交付时照常结算运费并将原物资批次移入前线；保险准备金使用原国库凭证退回国家。主动取消、超时、运费结算遭拒都不构成承保险故，准备金退还。保险生效后保费已赚取，退保不退保费。迟迟不出发的投保不会无限锁定国库准备金，服务器按保险出发等待期限关闭保险并退还准备金。等待期限从准备金和两笔保费阶段全部确认、保险首次生效的 `activatedAt` 开始；人工核验所花时间不会提前耗尽出发机会，刷新、重复命令和重启也不会延长该时间。

取消运输与退保只接受 `OPEN` 或 `IN_TRANSIT` 运输状态，先检查货物状态再释放准备金。已遭袭失败、成功交付或进入结算/复核的运输不能再用退保覆盖其实际结算结果。

只有承运者到达目的地、运输计时已结束、订单尚未超时，并由运输系统的持久风险判定记录为 `RISK` 遭袭失败时，保险才进入 `CLAIM_PENDING`。赔款使用已预扣的同一国库凭证向承运者支付，不再重复扣款。风险失败时间单独持久化，重启后即使已超过原订单期限，仍可按真实失败时间恢复合法理赔。

同一采购批次只能投保一次。已经有失败运输历史的批次不能通过新建运输单购买保险，以防先查看持久风险结果后反复承保。保险不覆盖取消、超时、玩家主动停止履约或资金不足；赔付与普通运费分别记录，不把赔付当作成功交货。

## 重启与人工核对

保险使用独立的 `plugins/StarSupply/insurance.db`，schema 为 v2。v1→v2 迁移增加持久化首次生效时间；旧版已生效保单使用已有最新更新时间作为可用的保守边界，尚未生效的保单继续等到真正生效时记录。备份应和 `supply.db`、StarCore 财政和经济数据、世界玩家存档成组进行。保险存储和货物存储由同一个序列化工作线程协调；周期恢复会检查已结束的运输，补全尚未登记的理赔或准备金释放。

保费扣款、保费入国库和保费返还的 StarCore 公共接口没有按业务 UUID 查询的独立回执。插件先把调用开始记录持久化，再调用相应服务；false、异常或重启后仍停留在调用开始的结果都转为 `REVIEW`。这些操作不会自动重放。保险结算或待核验期间，承运、交付和取消操作被冻结。

管理员核对独立经济证据后，可执行：

```text
/supply reconcile-insurance <保险UUID> <经济阶段> <applied|untouched>
```

经济阶段使用 `PREMIUM_DEBIT`、`PREMIUM_CREDIT`、`PREMIUM_REFUND` 或 `CLAIM`。`applied` 表示有证据确认该阶段已经生效；`untouched` 表示有证据确认未生效。仅比较当前余额不足以证明历史调用结果。

确认保费未扣时，取消保险并释放准备金。确认保费已扣、但尚未进入国库时，插件通过独立唯一编号返还承运者保费，再释放准备金；返还结果不明仍保持复核。确认理赔款未到账时，插件只重置同一准备金对应的未生效玩家入账阶段，再用原编号继续支付。确认理赔款已到账时，只完成本地确认，不再支付。

公共服务 `InsuranceApi` 的投保操作接受 `Player`，调用者须在玩家实体线程使用；操作执行玩家权限、国家身份、起点距离及可取消事件检查。只读报价和保险查询返回不可变记录。具体方法见源码中的 `dev.starsupply.api.InsuranceApi`。

该实现复用 StarCore 国库支出、退款、内部经济和 `TransactionFabric`，没有调用上游 `EconomyInsuranceService`：上游保险产品依赖其自身交易归属和领域结算处理器，无法直接表示 StarSupply 的实物运输失败语义。
