# 补给路线规划 API

`dev.starsupply.route.RoutePlanner` 接收节点和有向路段快照。调用方从 StarCore 的供给线和领土状态读取数据，转换成 `RouteNode` 与 `RouteEdge`，再把快照交给路线计算线程。规划过程不访问区块、玩家或数据库。需要双向通行的道路应提供两条相反方向、ID 各异的路段。

```java
var route = planner.plan(nodes, edges, warehouseId, frontierId, Set.of());
```

算法采用 Dijkstra，路段代价为 `距离 / 道路效率 × (1 + 2 × 敌对风险)`。封锁路段和 `excludedEdges` 中的路段不参与计算。路径风险按 `1 - ∏(1 - 路段风险)` 聚合。规划器本身不改变货物或资金；运输交付流程另外将护送后的路线风险与该实物批次持久化的遭袭值比较，遭袭失败时货物留回起点且不结算运费。

每次生成网络图都会重新查询 StarCore 对两端仓库区块的控制。任一端失去本国控制时，该路段显示为封锁，不能新建运输、领取或交付；恢复控制后可重新规划。失守也暂停新建采购、出售和加入起点护送，以及新建涉及该节点的道路。物资和既有合同保留在独立数据库，恢复控制不会复制或迁移库存，仍可按原状态恢复或取消。

每条道路的风险检查使用二维 DDA 遍历线段穿过的所有 X/Z 区块；恰好经过区块角点时也将相邻区块纳入保守检查。道路扫描最多检查 4096 个区块，超过上限的新道路会被拒绝，历史数据库中超过上限的道路在网络图中视为封锁，避免不完整扫描低估敌区风险。

返回值 `RoutePlan` 包括有序节点 ID、路段 ID、总成本和风险。地图或 GUI 可通过节点 ID 查询同一快照中的坐标。需要备选路线时，可把首选方案中计划避让的路段 ID 加进 `excludedEdges` 后重新规划。道路被封锁或恢复时，用最新快照重新计算。订单交付仍须按当前 StarCore 状态和订单状态校验。

开放运输最多登记四名护送者。已经登记护送的玩家领取同一运输时，会在领取事务中改为承运者并移除自己的护送记录；其风险与计时只计算其他护送者。`Logistics.transportRisk(shipmentId, prospectiveCarrier)` 让投保前报价采用同一口径。保险 `insuranceQuote(Player, shipmentId)` 适合展示给具体承运者，避免把自己的护送登记算入优惠。

缺失端点或无法到达时返回空结果。每张快照最多包含 10,000 个节点和 50,000 条路段。重复 ID、悬空路段、跨世界路段和超出范围的数值会抛出 `IllegalArgumentException`，便于调用方报告配置错误。
