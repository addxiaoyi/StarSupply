# 酒馆集合点与侦察情报

酒馆把商人、护送者和侦察兵聚集到本国领土上的实际地点。集合点和道路观察保存在独立 `tavern.db`，不改变国库或实物库存，也不需要常驻实体加载。

| 操作 | 规则 |
| --- | --- |
| `/supply tavern <集合点ID>` | 国家元首或司库持有 `starsupply.manage`，站在本国已占领领土登记；每国最多 16 个。 |
| `/supply untavern <集合点ID>` | 同样身份移除本国集合点。 |
| `/supply scout <道路ID>` | 本国成员实际到道路线段 32 格内观察，保存当时起终点、距离、效率、封锁与敌区风险快照。 |
| `/supply intel <报告UUID> <集合点ID>` | 抵达本国酒馆 8 格内发布本国报告；重复发布不延长有效期。 |
| `/supply board <集合点ID>` | 抵达本国集合点打开情报与公开物资合同 GUI。 |

默认报告有效 15 分钟，每国最多保留 128 份有效报告。情报板只显示本国在该集合点发布的未过期报告，以及本国 `OPEN` 采购和运输合同；合同交接仍需到仓库操作。敌方库存、国库余额和未侦察道路没有因此公开。情报描述的是观察当时状态，线路后来变化需要实地重新侦察。

查看和发布时重新验证成员国家、当前位置和集合点领土控制。集合点失守后暂停使用，恢复本国控制后可再次访问。移除集合点解除报告发布位置，报告可在另一处本国集合点重新发布，但原观察时间和到期时间保留。玩家退出国家后不能继续读取原国家的情报板。

开启森罗酒馆验证时，安装兼容 CraftEngine 与 KaleidoscopeTavernPlugin，配置：

```yaml
tavern:
  observation-radius: 32
  interaction-radius: 8
  report-ttl-seconds: 900
  require-authentic-beverage: true
  minimum-brew-level: 1
```

登记集合点时手持真实 Tavern 酒桶配方产出的酒品。适配器读取公开的 `CraftEngineItems.getCustomItemId`、Tavern `catalog().barrel()` 输出及 `brewLevel(ItemStack)`，检查物品身份和最低熟成等级，不扣除或改写酒品。API 不可用时验证失败。关闭该选项可在没有森罗酒馆时使用基础集合点玩法；界面会区分是否经过酒品验证。当前没有自动发现 Tavern 家具或把酒品当作情报货币。

观测半径可配置为 1–32 格，集合点交互半径 1–16 格，报告有效期 1–15 分钟。`TavernApi` 暴露与命令相同的登记、侦察、发布和读板操作；变更操作经过玩家实体调度线程上的可取消事件，随后由同一 SQL 工作线程持久化。详见 [公开 API](API.md)。
