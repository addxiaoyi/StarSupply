# 城市文本输入与会话生命周期

这是第十八份兼容补丁，按 [README](README.md) 在前十七份后应用 `starcore-city-input-recovery.patch`。固定 API 为 Paper 1.21.11，Java 21；Core 原始基线为 `f769e62799e769a18fe51305b545869a17f80cd1`。

## 修复行为

城市金额书本曾替换主手物品，断线时清除备份引用；名称和公告也依赖内存书本备份。现在三处都使用 Paper 原生文本窗口，无真实背包替换。名称最多 32 字、公告最多 100 字且支持多行，金额按已有精确十进制协议解析。输入只产生预览，创建、保存和付款仍需显式确认。

输入会话绑定原 Player 连接、原国家或城市，五分钟过期。窗口发布与响应均进入玩家实体调度；旧窗口、其他玩家、重连、重复响应、退出、停用、离线与调度退役不能复用旧回调。停用先关闭输入再关闭资金服务。名称创建重新核验国家创建者，公告核验原城市市长，金额核验原城市成员、市长及资金权限。名称/公告草稿与预览匹配后才可提交，保存失败可重试。

## 保留边界

- 已丢失的历史物品无法根据当前状态自动恢复。其他模块仍使用 `BookInputSupport`，内存备份、停用、崩溃和背包交互需独立处理。
- 城市其他 GUI 会话、邀请目标、传送、权限和线程归属仍需审计；同城公告清空确认尚未绑定内容版本。待恢复资金安全取消和旧账核对不在本补丁中。
- 停用拒绝未准入回调，已经越过最终检查的操作可以完成；这不是耐久业务取消机制。
- 原生窗口真实客户端显示、Escape/关闭体验、Paper/Folia 全组合、生存和视觉验收待验。未启动服务器或修改世界、玩家存档。
- 共享国家解散、其余外部退役、全仓干净构建、最新 MySQL 和容量仍待完成，详见 [代码清单](../CODE-CLOSURE.md)。
