# 外交关系持久退役

这是第十九份兼容补丁，按 [README](README.md) 在前十八份后应用 `starcore-diplomacy-retirement.patch`。Core 固定原始基线为 `f769e62799e769a18fe51305b545869a17f80cd1`。

## 协议与接线

`DiplomacyRetirementService.retireDiplomacy(operationId, nationId)` 在一次持久提交中清理目标国家的外交关系、外交战争记录、当前冷却/邀请、旧冷却/邀请和停战请求，并保存不可变回执。回执保留原操作 UUID、国家 ID 和清理条目数（按七种存储数组分别计数）。同号重试返回原结果，不再次清理；异号请求同一国家会被拒绝。其他国家、旧状态家族及无关元数据保留。

调用方须先持久授权解散；不提供重新开放或取消。`StarCoreApi.diplomacyRetirementService()` 和服务注册表暴露入口。现有 `NationDisbandRecovery` 使用原解散 UUID，并校验回执归属；后续联盟清理失败时，重启读取原结果继续。仅实现旧关系接口的第三方服务仍走旧清理，不具备新持久退役保证。旧 `clearNationRelations` 保持普通清理语义，不自动变为永久退役。

外交普通关系、邀请和战争记录修改在提交前检查最新权威；另一个实例已更新则加载新快照并要求重试。新 API 与存储两层拒绝退役国家关系、回执删除或变更。模块准入防止并发修改和事件重入；停用不将未提交的回调状态刷入存档，启用失败会清理监听器和自身服务注册。

## 存储与升级

文件继续使用 `diplomacy/relations.properties`，增加完整校验和及 `diplomacyRetired.<国家UUID>` 回执。普通写入严格同步并校验旧内容；检测到已加载权威缺失，或文件不存在但有备份/临时文件时，拒绝静默回退。损坏、重复属性、缺字段和超出数组计数的历史条目需要独立证据修复。

SQL 使用既有 `starcore_diplomacy_state` 表，在同一事务内校验版本、保留不可变回执并替换完整快照。保留旧版本行语义；空数据但版本非零时拒绝自动迁移。文件迁入 SQL 会保留原回执。后端在构造时固定，运行中数据库出现不会自动切换文件权威；切换需停止旧写入者并明确重启配置。

`saveAsync` 兼容入口现同步报告失败。文件仅支持单进程；SQL 多实例必须使用同一新协议，不能混跑旧写入者或独立文件/数据库权威。完全丢失权威、版本和备份后的历史不能被当前代码重建。

## 剩余范围

国家解散仍使用独立文件日志；联盟、军事联盟、实际战争和赔款权威尚未全部持久退役。本补丁的外交战争记录不等同实际战争状态，不能据此宣布国家解散闭环。

只读关系缓存可能滞后至下一次准入或重载；跨模块没有事务隔离。已经开始提交的操作可在停用后结束；结果不明且读回失败时停止新修改，需重启或显式重载恢复。派生事件仍为尽力发送，容量/归档、其他模块输入、全仓干净构建、最新 MySQL、Paper/Folia/生存/视觉仍待完成。未启动服务器、扩大 profile 或修改世界与玩家存档。
