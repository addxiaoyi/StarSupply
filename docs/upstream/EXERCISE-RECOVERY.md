七种演习类型均可启动。双方统计覆盖全部成员，队长耗尽兵力后只要队友还在就继续；自由对抗允许 FREE 阵营互战。同一对国家的 60 秒冷却双向共享并跨重启保留。修正默认负数惩罚再次取负、反而增加失败方士气的问题。只在启用奖励且发生过模拟战斗时结算国家经验；单纯开始后立即结束、仅玩家死亡或取消不产生经验。

演习仍是国家训练模拟，输入人数与伤亡不预留或扣减真实军队。超时按开始后的真实经过时间计算，暂停期间也计时。版本 1 从耐久终态按固定算法重建结果，今后变更排名或奖励算法必须迁移存档版本。

## 奖励协议与存储

最终结果先落盘，作为奖励意图；每个参演国家使用 `exercise-reward:<演习 UUID>:<国家 UUID>`。新增 `NationExperienceService` 在同一国家快照中提交经验及原编号回执；演习端读取并核对回执，再保存已确认标记。经验已到账而演习确认中断时，重启读取原回执，不再次加经验。单个收件国家暂不可用时，其余国家仍可完成奖励。

国家经验支持现有文件/SQL 权威。文件保存使用原子替换、保存前字节比较及同进程路径锁；SQL 保留版本比较写入，读取和迁移验证回执快照，已发布但被清空的数据表不重新导入旧文件。损坏、重复字段、校验不一致或缺失主文件时停止写入，不自动回退旧备份。不明确的提交结果冻结旧服务引用；明确丢响应可通过精确读回确认。

新经验发放检查国家创建、分裂和解散恢复日志；未完成的生命周期事务先恢复，防止历史快照覆盖新经验。已完成分裂保留原国家回执，不复制给新国家。国家常规保存改为等待提交，避免异步旧快照抹掉回执。公共 API 基线已审查更新，只有新增签名。

演习文件固定为插件目录下 `exercise/exercises.dat`，即使国家使用 SQL 也一样。两类文件上限均为 64 MiB，文件模式需单个服务器进程持有。演习不提供跨服务器共享 SQL 权威；历史回执和演习记录暂未有界归档。

## 使用与权限

主 `config.yml` 的 `exercise` 区段是实际配置来源，`exercise.yml` 仅作参考。人数、时长、等级、士气、整数经验、自动开始和奖励开关在创建时冻结到演习。配置修改用于新建演习。

```text
/exercise create <名称，可含空格> <att_def|ffa|sim|tactical|siege|retreat|recon>
/exercise join <id> <模拟兵力>
/exercise leave <id>
/exercise zone <id> <半径>
/exercise start|pause|resume|end|cancel <id>
/exercise battle <id> <对方国家ID>
/exercise info <id>
/exercise result [id]
/exercise rewards
/exercise recover
```

变更须有基础权限及对应子权限，参演国操作须由国家创始人/领袖执行，管理演习须由组织国领袖或管理员执行。完整 UUID 与唯一 4–8 位短 ID 使用同样检查；歧义拒绝。`rewards` 和 `recover` 仅管理员可用，也支持控制台。`end` 沿用 `cancel` 权限；`pause/resume/zone/battle` 沿用 `start` 权限。

自动模拟战斗和死亡统计需要预先设置区域，使用命令时玩家所在位置为中心；移动检测要求双方均在区域内且距离不超过 30 格。未设置区域时只支持显式 `battle` 模拟。监听读取真实国家成员，分别在玩家所属实体线程读取位置和发送消息，并在发起方线程重新确认位置、国家归属和会话。模块停用撤销订阅、取消任务、使旧命令/服务失效，并只注销自身服务，避免误删替代实例。

启动、分钟维护、重复结束和管理员命令都能恢复待确认奖励。管理员查询显示原编号；缺少原国家的奖励继续保留，当前没有安全放弃、转发或改收件人的协议。通知与资源区刷新为保存后的尽力操作，进程中断可能丢通知，不构成奖励到账凭证。
