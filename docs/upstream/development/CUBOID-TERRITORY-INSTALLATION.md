## 固定选择与确认顺序

`cuboid-installation.properties` 使用带校验和、初始化标记和 CAS 的持久存储。第一阶段保存来源、目标后端、绝对目录及适用的实际 SQLite 身份摘要；第二阶段绑定已确认权威 UUID。选择摘要同时进入新领土权威的不可变来源证据。

第一次调用要求调用者已停止所有旧 cuboid writer。本组件不会把旧独立文件保存变成事务，也不会自动停止其他进程。文件来源复用 T3 的原文件锁、恢复残留与备份检查；SQLite 来源复用 T2 的完整快照和显式出生点世界对应。SQL 空表、损坏或异常均不会回退到文件，选用某来源不合并另一份来源。

旧 SQL 缺少出生点世界时，初次导入必须提供对应关系；缺失可在尚未提交新权威时补齐重试。对应关系摘要保留在领土权威中，后续启动不再应用这些映射，也不重导入旧数据。来源选择本身永久固定，选错待初始化来源需要另行核实恢复，不能改配置直接绕过。

## 数据库身份与恢复

`CuboidTerritoryStorage.bindSqlite` 提前核对实际 SQLite 产品、URL、唯一持久 main 数据库及真实文件路径。同一个固定 wrapper 贯穿原 SQL 读取和目标提交。即使注入的 DataSource 在导入或提交时更换数据库，也不能把数据提交到另一库。

选择保存失败时不能初始化目标；目标已提交但 UUID 绑定失败时，下次可以读取原目标并完成绑定。迁到文件目标后，正常重启和未完成绑定的恢复不再要求原 SQLite 在线。新权威缺失、UUID 被替换或不属于原选择时拒绝重新导入；有权威却没有原安装记录时也不会自动接管。

绝对目录属于当前绑定：迁移部署路径和错误待初始化选择的修复流程仍待实现。SQLite 绑定仅保证本协议读写连接的身份与提交边界，不等于跨进程实时缓存同步或停止外部旧 writer。
