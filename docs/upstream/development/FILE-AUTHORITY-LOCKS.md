## 已实现

原来的静态锁只能约束同一个 JVM。多个服务器进程可能同时比较到旧文件，随后相互覆盖已确认回执。现在以下九类权威在读取、比较、保存及读回确认时使用操作系统文件锁：国家目录、领土、国库、城市、外交关系、双边联盟、军事联盟、多国联盟、战争/和约/战场/实际赔款。

锁位于稳定的 `<目标文件>.lock` 中，和被原子替换的业务文件分离。同线程可重入，路径规范化并解析父目录真实路径，目标文件及锁文件符号链接被拒绝。等待本地锁和操作系统锁共用五秒预算，竞争超时、线程中断或不支持文件锁会拒绝操作；文件系统调用本身不承诺五秒内结束。原始版本检查继续拒绝已经过期的业务快照。

`AtomicFilePersistence` 的替换、恢复和删除使用同一个锁，防止恢复/删除清理另一个活跃进程正在写入的临时文件。锁文件永久保留；是否存在该文件不表示有活跃写入者。运行期间删除或替换锁文件会破坏锁身份，因此存储运维须保留它。常规文件加载按原后缀筛选，锁文件不作为存档或恢复候选。

这套协议要求写入者使用相同机制。旧版写入者、外部替换目录或锁文件、硬链接别名、网络文件系统、混用两个后端及完整多服玩法不在本轮保证内。迁移仍需停用旧后端写入者。其他业务仅调用原子替换并不会自动获得旧业务快照检测或跨权威回执。

## 验证

七个互不重叠的测试选择合计 **2,198 项、261 套件通过，0 失败、错误或跳过**：

- 42 项文件专项：15 项多进程/锁行为与 27 项既有原子文件测试。
- 133 项解散联合/准入与 817 项既有相关回归。
- 450 项城市/领土/国库与 90 项外交回归。
- 487 项存储、Clan、Faith、海军和演习等调用方回归，另有 179 项蓝图、副本、UGC、联盟保存及其他调用方回归。

九类文件竞争均使用两个独立子 JVM 选择同一旧状态；持锁时双方不能提交，释放后恰有一个成功，失败者不能覆盖赢家回执。第三个独立 JVM 的加载也等待锁并成功读回。另覆盖持锁进程强杀后重获锁、临时文件写到一半强杀后保留上次确认快照、已确认提交后强杀仍可读取、竞争删除不移除原件/临时件、重入、中断与锁文件打开失败后重试。子进程使用真实存储，无 Bukkit 启动和存储模拟；只终止测试自己创建的子进程。

测试在本机 Windows 文件系统运行。Maven 每批使用 128 MiB，子 JVM 使用 64 MiB；联合/准入与既有回归两批曾时间重叠，其余批次串行。所有套件按最终 XML 去重并核对实际选择。进程中断证据限定于存储边界，尚非完整 NationModule 解散流程的进程强杀恢复。

66 个累积生产源、44 个选定测试源在空目录编译；135 个生产 class、76 个测试 class 与最终测试输出一致。保留原依赖和未修改 class，这不是全仓干净 Core 构建。普通 API 兼容检查通过，可达基线较上个开发检查点未变化。独立检出正向/反向补丁检查通过，全部 3,689 个 src 文件、API 基线和 pom.xml 逐字节一致（统一换行后）。详见[完整证据](../../verification/workspace-file-authority-locks-development-20261126.json)。

扩展回归暴露了一条旧国库生命周期测试，原断言在停用后查询余额；现同时验证迟到刷新没有修改余额及旧服务拒绝查询。初次该批失败，并有两项依赖环境的 MySQL 测试跳过；保留失败日志，最终本地选择明确排除 MySQL，未计作通过。早期子 JVM 日志句柄和只读探针问题亦已修复，失败尝试未计入最终数量。
