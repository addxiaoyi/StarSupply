## 旧 SQLite 一致快照

`CuboidTerritorySqlImport` 通过实际持久 SQLite 连接，在同一次读取事务中读取五张原表：领土、子区域、双方权限及统一成员。它要求完整且已知的表和列，区分整套表不存在与存在但数据为空，检查原 UUID、数字、布尔值、权限、成员、父子关系和边界。缺表、视图替代、未知列、孤立或重复记录、残缺权限、部分出生点均拒绝整个导入，不使用旧容错 loader，也不切文件。

原 schema 和确定性完整行摘要作为导入证据保留。行数、单字段和总 UTF-8 数据量有上限；排序使用缓存的规范行键。SQLite WAL 下，测试在读取过程中由另一连接修改父子表，导入仍得到原完整快照；随后新导入读到修改后的数据和不同摘要。该验证不代表源库与新权威的原子切换：真正激活前必须停止旧 writer。

旧 SQL 只保存出生点坐标，**没有保存出生点世界与朝向**。有坐标时必须提供按原领土 UUID 指定的世界对应关系；不会猜测其等于领土世界。缺失、未使用或无关对应关系拒绝导入，明确对应关系的摘要独立保存。旧 SQL 未记录的 yaw/pitch 使用 0。旧子区域创建时间在本次导入完整保留。

## 旧对象仅作为显示视图

`CuboidTerritoryViews` 和包内构造器把原完整权威映射成独立的 Territory/SubRegion 对象，保留创建时间、所有业务字段、权限、成员和出生点朝向，不使用反射。子区域索引从活动关系派生，已删除记录不显示。

每次获取创建新对象；修改视图的 owner、成员、权限、出生点 Location 或子区域描述不会改动存档或其他视图。世界暂不可用时视图出生点为空，持久原坐标仍保留，之后的新视图可重新解析。世界解析器返回错误世界时直接拒绝。没有提供把这些可变视图自动覆盖回权威的入口。
