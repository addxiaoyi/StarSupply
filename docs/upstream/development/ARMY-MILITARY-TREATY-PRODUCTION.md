# 军事与混合和约生产接入 A14 开发检查点

本阶段把已验证的 War/Diplomacy/Army 协议接入实际 `PeaceTreatyService` 和 Army/War 模块。玩家可以提议、查看并接受仅军事或政治＋军事和约；任一接收器仍待处理时，和约保持待恢复且不能释放 War 预留。新条约继续保留完整原条款、原编号、三层哈希和不可替换的接收器分配。

## 冻结计划与完整终态

schema5 在源批次中保存 Army 原请求和冻结计划哈希，以及独立的永久终态证明。完整军队前镜像继续由 Army 权威保存；源保存的是可核对的计划引用，恢复时读取原权威并重新计算哈希，不能重新选军队或替换计划。源编码显式拒绝把军事批次降级到 schema1–4，旧纯政治 schema1–4 / v1 / v2 继续按原哈希和回执读取。

外交接收全部政治索引，军事接收全部军事索引；仅军事和约仍保留外交 receiver 来结束原战争关系。军事多条限制取最严格值，任一缴械条款均为全部缴械。两端预留完成后，源先持久保存共同 binding 决定，再调用两端 bind；另一实例若此时取消，必须完成该 binding 并走原 War seal，不能把一端当未绑定封存。

War 结束后仍先确认外交决定，再由 Army 核对原 War 与外交终态并提交。ACK 保存双方一致终态，所有原条款标记完成后才显示 ACCEPTED。终态向量包含精确 manifest entry、phase、时间和来源回执；War release 返回值必须与源保存的完整向量一致。外交否决、SUPERSEDED 或取消不产生军事效果。

## 取消、容量与启停

共同 binding 尚未保存且两端均未绑定时，先保存取消意图，再分别永久封存原请求；接收器未曾 reserve 也可以完成。任意封存回复、ACK 或 release 丢失都按原编号恢复。共同 binding 已保存时，保留原计划并完成缺失绑定，随后按原 War seal 取消；已经存在原 War end 时继续完成原和约。

源 quota 保留至 RELEASED；军事源仅保存固定大小的原请求／哈希引用和证明，不重复完整军队快照。军事步骤只允许原 operationId 与 militaryPlanHash；不能添加不属于协议的赔款、贡纳等 sidecar。新增容量检查覆盖双证明、少一字节拒绝、源和原生释放先后，以及最大 4,096 项外交计划的未绑定取消。

ArmyModule 注册接收器，停用时先关闭并按实例注销，再关闭共享 Army authority；启用失败同样清理。WarModule 将同一接收器交给原生 War 证明读取器和生产和约编排。旧服务关闭或来源在回调中关闭后拒绝继续推进。限制查询读取 Army 权威的实际生效结果，返回脱离视图；显示对象的 lift 不修改实际限制。
