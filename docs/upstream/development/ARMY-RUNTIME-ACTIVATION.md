## 统一的军队写入边界

ArmyService 不再维护可变军队 map、定时全量保存或失败后写回旧快照。旧 getter 与 snapshot getter 均返回脱离权威状态的 ArmyUnit / Location；修改返回对象不会改变军队。全部已存在的 ArmyService / Commander writer 改由 ArmyAuthorityOwner 提交，`restoreArmyStates` 明确拒绝，`persistCurrentArmyState` 只确认可读状态。

生产构造器固定使用 persistence 的 `army` 命名空间下的文件权威，包括其他 Core 模块使用 SQL 的配置。SQLite 实现在本阶段通过真实持久数据库注入验证，但尚未成为生产 Army 后端选择。旧 `armies.dat` 原字节只导入一次，原文件和迁移证明保留；精确名称世界绑定到 UUID。损坏的旧源阻止初始化，不能写成空军队覆盖。重启取消原 ACTIVE 战斗并释放遗留 ATTACKING / SIEGING 状态，保留已提交的技能效果和永久证明。

创建、补给、移动、状态、攻击和解散增加 Player 入口，重新校验在线状态、当前成员身份、NationPermission 和目标归属；命令及 GUI 使用这些入口。无玩家参数的兼容 API 保留给可信服务集成。新战斗还需双方国家开放、当前处于战争、距离及进攻方补给/士气满足条件。每分钟维护整批提交，跳过原付费预留、ACTIVE 战斗和关闭国家。

## 付款和管理员恢复

资金来源明确固定为 **直接 Treasury 国库余额**，不消费 Budget pool。先保存包含操作者、原价格、容量和精确军队效果的付费意图，再查询或调用原编号 NationDebitService。价格以 BigDecimal 相乘；创建整数溢出不会低价扣款。相同操作者的同输入待恢复创建或补给复用原号；改变输入需先处理原请求。取消若发现已扣款，完成原购买效果，不执行退款或创建第二次扣款。

管理员和控制台可使用：

- `/army recovery list`：确认存储后列出未完成付款，并显示普通业务是否暂停。
- `/army recovery show <操作编号>`：读取原操作事实。
- `/army recovery retry <操作编号>`：按原号恢复；不改变报价和目标。
- `/army recovery cancel <操作编号>`：请求原号安全取消；已扣款时仍完成原效果。
- `/army recovery resume`：完整读回、结清原付款、取消中断战斗并规范旧状态，全部成功后开放普通业务。

这些入口要求 `starcore.admin`。启动恢复遇到国库或读回故障时保留服务和命令，普通新写入及维护暂停。仅刷新诊断数据或完成某一笔付款不能清除完整恢复屏障。初始化前旧数据损坏仍会阻止服务创建；这与已能打开权威但业务恢复暂时失败不同。

## 指挥官和战斗

Commander 在自己的同步边界内确认当前学习等级，再调用 ArmyService 校验身份、权限、目标和敌对关系。技能效果、所有相关战斗干预和完整 UUID 冷却链一次提交。失败准入、无效目标、权限或状态拒绝不消费冷却；已接受的封顶、无数值变化以及 SCOUT 操作保存证明并消费冷却。旧 UUID.hashCode 冷却 map 和直接 ArmyUnit 修改已删除。

WarArmyIntegration 开始战斗时保存双方同次转换，完成/取消始终使用原 session ID 和最新干预快照。结果展示失败不会回滚伤亡或复活军队。伤亡校验限制士兵数及士兵数乘生命比例的总量；幸存者生命比例上升但总生命下降不再误拒绝。单军增援继续受配置上限约束。

Commander 的学习、经验数据仍使用原有持久队列；本阶段切换的是实际施法效果与冷却。攻城的领土转移仍为原有独立路径，尚未具备与 Army 共用的持久结算协议。

## 国家关闭、退役和启停

Nation 在持久确认 War 解散准入后，逐个目标国家保存并读回 Army 关闭；全部完成后才能删除国家目录。关闭编号由原解散号和国家号稳定派生，父国与城邦互不混用。Treasury 退役前，先为所有目标国家结清原付款、取消原战斗、确认 Army 全量退役；原操作结清不依赖已经删除的国家目录。启动也为历史已完成解散补齐 Army 退役。

停用取消 Army 计时器、以原号取消战斗并永久关闭 owner；War 集成清理失败时仍执行 Army 清理。模块只注销自身注册实例、命令和监听器，启用失败走同一清理路径。Commander 关闭后拒绝新施法和队列写入，并提供已有队列的 drain future。
