## 行为与恢复

解散先将完整原请求保存为 `ADMISSION_PENDING`，国家及城邦仍保留在目录中。战争、和约、战场和实际赔款使用同一持久权威，在其版本检查下保存不可改写的准入决定。活动战争、活动赔款、待结算付款、待执行和约或战场积分会拒绝解散。

准入接受时永久预留原国家集合。新战争、赔款及相关和约/战场效果不能绕过预留；其他国家仍可写入。国家模块核实返回回执与权威读回一致后，才提交 `CLEANUP_PENDING` 并移除目录，沿原编号完成八类退役，最后保存 `COMPLETED`。提交后丢响应或重启使用同一请求和决定继续；恢复清理前再次核实原准入回执。

拒绝保存为 `REJECTED`，国家保留。即使战争后来结束，重试原解散仍返回原拒绝；再次发起解散使用新编号。`/nation disbandrecovery show|retry` 显示原状态，拒绝记录不会进入待恢复列表，也不会触发旧完成记录的联盟补齐。旧共享 `CLEANUP_PENDING`/`COMPLETED` 记录可继续恢复，旧独立日志仍需人工依据独立证据核对。

接受后的预留没有取消或过期机制。无法核实回执时暂停该流程；不得换号重做、删除历史或根据余额差推断成功。宣战手续费仍使用另一条国库扣款/退款路径，本补丁不提供其跨重启交易协议。

测试发现并修复文件转 SQL 的迁移缺口：空 SQL 权威现在导入当前封存文件，包括准入及退役回执；缺失、损坏的文件拒绝迁移，不能退回旧表重建状态。迁移需停用旧后端写入者，本轮未验证双后端同时写入。

## 尚未闭环

文件存储仍仅有 JVM 内的静态锁，没有操作系统级文件锁；多个服务器进程共用同一目录的保护尚未实现。本次并发线程测试不能证明多进程安全。SQL 多进程、进程强杀恢复、最新 MySQL、完整 Core 干净构建、历史回归全集和最终配套成品也待验。
