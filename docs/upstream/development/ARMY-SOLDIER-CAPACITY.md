# Army 国家总兵数配置 A9 开发检查点

日期：2026-11-27，Asia/Shanghai。

本检查点为 A8 运行时增加国家总兵数准入。创建和指挥官增援共同计算现有兵力与待完成建军预留；额度不足时在付款或冷却前拒绝。原付费请求记录接受时的上限，重启、丢确认和降低配置后仍按原编号完成。这是运行时配置额度与原操作预留，军事条约的永久限制、裁军和 receiver 尚待实现。

## 配置和玩家反馈

新增 `army.max-soldiers-per-nation`，默认配置为 10,000。旧配置缺少此键时，采用 `max-armies-per-nation × max-soldiers-per-army` 的 long 乘积，保持原有默认规模；旧三参数 ArmyConfig 构造器仍可调用。值为 0 时禁止新的兵力增长，不会自动裁撤已有军队。负值及协议保留的 Long.MAX_VALUE 哨兵被拒绝。

`/army list` 展示现有兵力、有效上限和待完成建军人数。新建军队同时受军队数量、单军人数和全国总人数约束；REINFORCE 同时受单军和全国人数约束。其他国家独立计算。战斗参与者只按当前 live 快照计算一次，不重复加入 session 内的历史快照；取消战斗保留最新增援人数。

## 原请求预留和写入校验

待完成 CREATE 预留其完整兵力，包含取消请求尚未获得负面资金决定的操作。当前兵力与这些预留之和不能超过任何未完成创建的原始上限。此约束由权威存储校验，直接 owner 创建或增援也不能挤占已接受的额度；另一个实例使用旧快照提交会触发 CAS 冲突，重载后仍看到原预留。

新 REINFORCE 请求也记录上限，存储在提交技能效果与冷却前按当前完整兵力和预留复验。失败不会留下技能或消耗冷却。统计用 long 加法，多个超大军队不会发生 int 回绕。

原号付款被确认 APPLIED 时，预留变成相同数量的现有士兵，不重复占额；确认取消或其他永久负面结果才释放预留。降低运行时配置不会抹除原接受条件或再次扣款。已有军队超过新配置时，补给、移动、解散和原操作结清仍可进行，新增长拒绝。关闭国家也能结清有限额的原付款、战斗和增援历史后完成退役。

配置本身不是持久化的条约政策：不同运行实例的配置必须由部署方保持一致；本阶段未提供跨权威永久军限、解除限制或裁军证明。后续军事 receiver 需要把这些事实存入 Army 权威，并接入完整和约 manifest/终态流程，不能把此配置直接当成条约履约。
