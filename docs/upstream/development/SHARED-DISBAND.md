## 本轮实现

- 国家目录删除与原解散请求在一次共享快照中提交，外部清理完成后再提交永久终态。删除父国家及城邦时不会出现只有目录、没有恢复请求的中间状态。
- 文件与 SQL 存储校验状态转换：原请求及完成历史不可删除或改写；拒绝重新写入已解散国家及其未清理的子国。待清理时暂停目录其他写入，创建、圈地、分裂和普通保存都保留解散记录。
- 恢复沿原事务号调用领土、国库、城市、外交、双边联盟、军事联盟和战争退役服务。共享流程在提交前要求这七类服务支持持久退役；回执必须属于原操作与原国家，错误回执不能推进终态。
- 实际 `NationModule` 接入上述流程和启动恢复，阻止预检查及清理回调重入。另一实例在预检查期间修改过国家时，原解散选区会被拒绝；提交丢响应后读取权威确认，无法读取则冻结旧实例。
- 实际启动恢复入口不再按旧日志中的国家是否存在推断提交结果。旧独立解散日志保留并阻止自动处理，等待独立证据核对。旧兼容恢复辅助函数仍在源码中，后续需迁移或移除；本轮没有把它们作为新共享协议使用。

## 尚未闭环

1. **独立多国联盟**：`module.alliance` 仍分别保存联盟、成员、国家索引、邀请、关系和公告，缺统一权威及永久退役。它尚未接入这次共享清理，不能将当前终态解释为整个插件的国家解散已经完成。
2. **恢复运维与历史**：共享解散缺少专用查询/重试管理命令；旧日志及旧无回执外部效果没有自动迁移协议，需独立证据核对。当前一个待清理解散会暂停整个国家目录的新写入。
3. **跨模块业务**：宣战收费、普通结盟/解约、和约政治/割地/裁军效果仍缺完整接收回执；准备转账缺安全取消。活动赔款阻止解散的现有业务限制仍保留。
4. **其他阶段与发布**：其余物品输入、海军/伤兵/学说玩法、调度与启停、耐久通知、归档容量、全量构建和成品验证继续按[代码闭环清单](../../CODE-CLOSURE.md)处理。
