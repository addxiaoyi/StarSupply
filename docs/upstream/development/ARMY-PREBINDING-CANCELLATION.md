# 和约绑定前取消 A13 开发检查点

日期：2026-11-27，Asia/Shanghai。

在和约请求已经保存、接收器尚未完成绑定时取消，必须封存原请求。先前的生产恢复会继续预留和绑定，然后才尝试取消；接收器不可预留时，取消也会被阻塞。本阶段增加无需新增预留的持久取消，并接入现有空／纯政治和约的生产恢复入口。

## 原请求永久封存

Diplomacy 的 `abandonUnboundTreaty` 接收完整 v2 请求。请求不存在时保存无计划的 `SUPERSEDED` 终态；已经预留时保留原计划并保存同一终态。迟到的预留返回原结果，绑定不能越过终态。这种未绑定结果不包含 effect proof，不能据此结束战争。

Army 的 envelope 取消接口同样支持请求尚不存在的情况：保存完整原条款和无效果的 `CANCELLED` 记录，不冻结或裁撤军队。已预留则保留原军队快照并释放预留。尚有付款／战斗，或者国家正在关闭／已经退役，都可以封存尚未预留的请求；军队、墓碑和其他账本必须完全不变。请求编号和原 envelope 不可替换。

已有 binding 的请求拒绝走本地取消路径。生产恢复重新读取实际接收器；若绑定抢先提交，恢复原 binding 并沿既有 War 取消证明完成，不用无绑定终态覆盖已绑定状态。

## 生产恢复与容量

取消意图先保存到原批次。接收器仍未绑定时，直接调用封存接口，再保存终态和释放记录；没有新的接收器 reserve/bind，也没有 War 准入或结束。取消意图未保存成功不调用接收器；封存后丢回复、ACK/释放保存失败、服务在回调中关闭，均按原编号重启恢复。原 War 结束已经提交的情况继续遵循既有“完成原和约”规则。

Diplomacy 为未绑定的预留保留未来封存字节和一个 SQL revision；其他写入不能消耗这部分容量。Army 的完整预留／封存继续经过同一存储的未来容量检查。

War 源记录在 PREPARED 阶段即保留取消结果所需空间。即使接收器已经冻结计划而回复丢失，也能保存完整原计划和终态。未绑定配额取不可变原请求的保守大小，加最多 4,096 个 pair plan 的 8 MiB 预算；绑定后切换到已有完整 manifest 的配额。该空间直到源批次 RELEASED 才释放，并保留已存在的原生 War 准入配额。剩余容量不足会明确拒绝新操作。
