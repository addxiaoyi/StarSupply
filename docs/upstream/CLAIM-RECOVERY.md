# 圈地付款与领土批量回执恢复

这是第十三份补丁，在前十二份（最后为 [建国/城邦恢复](CREATION-RECOVERY.md)）之后应用 [starcore-claim-recovery.patch](starcore-claim-recovery.patch)。固定上游仍为 `f769e62799e769a18fe51305b545869a17f80cd1`。本补丁随 StarSupply 分支提供，不直接推送 Core。

原圈地流程先普通扣款、再逐块写入领土，失败时仅用内存列表撤地并发起不检查结果的普通退款。服务器中断后无法确认原报价、付款及部分领土是否保存。现在新圈地先将原请求、国家、完整选区、原报价明细和限额写入国家目录，扣款、领土批次与退款都使用由该操作 UUID 派生的固定编号。

## 提交与恢复

1. 将 `PREPARED` 意图与当前国家目录、创建历史、圈地历史共同提交。成功前不扣款、不占地；重试不重新报价。`NationClaimService` 是独立公开接口，通过 `StarCoreApi.nationClaimService()` 获取。
2. 玩家资金使用 `PlayerMoneyService` 原编号扣款及权威查询。余额变化不用于推断结果。拒绝付款也保留终态，后来有钱不改变原请求结果。
3. 整批地块和不可变领土回执在同一个文件快照或 SQL 事务中提交。重叠或超限时整批拒绝；新协议没有逐块成功的中间状态。回执保留原持有人、完整地块、原限额与 `APPLIED` / `OVERLAP` / `LIMIT_REACHED` / `CANCELLED`。
4. 领土已提交时记录 `CLAIMED`，后续查询与重试只返回原回执。撤地、转移及重新占领不会删除回执，旧请求不能重新生成地块。
5. 批次拒绝时先持久化 `REFUND_PENDING`，再沿原退款编号退回原金额。未知结果保留该编号；权威退款拒绝成为 `REFUND_BLOCKED`，只有显式重试先保存下一次退款编号。

普通 `claimSelection` 和单块 `claimCurrentChunk` 已接入该流程。旧签名没有 UUID，因此只自动匹配同一玩家、同一选区的**待恢复**请求；需要跨终态安全重放的调用方应保存公开接口的原请求 UUID。完整国家快照保存、创建与分裂都保留圈地历史；同一目录暂只允许一个待恢复创建或圈地意图。扩展回调重入及停用旧引用会被拒绝。

## 管理入口

控制台或具有 `starcore.admin` 权限的操作者可以执行：

```text
/nation claimrecovery list
/nation claimrecovery show <完整操作 UUID>
/nation claimrecovery retry <完整操作 UUID>
/nation claimrecovery cancel <完整操作 UUID> confirm
```

取消先持久化 `CANCEL_PENDING`，再核实原扣款及领土回执。若领土已经提交，成功结果优先，取消不会撤地或退款。若尚未提交，保存 `CANCELLED` 领土回执，拒绝迟到执行者，再沿原编号退款。为防止迟到执行者在退款后重新扣钱，取消也会封存原扣款编号；这可能执行一次原扣款并立即退款，资金拒绝或结果不明则按相应状态处理。已完成的付款/领土操作不能通过这个命令倒带。

## 领土存储变更

文件模式仍使用 `territory/claims.properties`，新增批次历史与全快照校验和，使用版本字节比较、原子替换与读回确认。文件、字段或记录不完整时拒绝继续；不自动把备份当成最新权威。文件模式只支持单进程。

SQL 模式保留 `starcore_territory_claims`，新增 `starcore_territory_batch_receipts` 和 `starcore_territory_revision`。普通占地、撤地、转移和批量操作共同参与版本检查；领土与回执同事务保存。读取检查前后版本与完整校验和，不再凭进程内旧缓存判断归属。首次迁移释放读取连接后才提交，可使用单连接池。已发布的空 SQL 状态不会重新导入旧文件；权威表/版本行丢失或绕过协议的修改会拒绝服务，需独立核对。

存储后端在服务生命周期内固定，数据库中断不回退文件。必须停用旧写入者后升级，不能混跑旧版异步领土写入协议。旧领土严格迁移，但补丁实施前没有圈地意图与资金回执的半完成交易不能自动补造证明。

## 已验证与待完成

本轮使用真实原子文件、真实 SQLite、真实玩家资金实现与有界故障注入，验证提交前后中断、读回失败、扣款/领土/退款响应丢失、取消与迟到恢复、整批重叠/限额拒绝、相同地块与同持有人限额的双写者争用、退款拒绝后显式重试、普通目录保存/分裂历史保留、权限、停用及回调重入。选区构造器的计数溢出和整数最大坐标循环也已修复。精确测试数量、产物哈希与补丁重放结果见 [验证记录](../verification/workspace-claim-recovery-20261126.json)。

本补丁收口的是**新圈地付款、整批领土提交与原编号恢复**。仍需继续开发/验证：

- 完整国家分裂/解散跨实例意图、迟到副作用与外部清理协调；目录版本保护不能替代整个生命周期协议。
- 圈地提交后的资源区刷新、发展提示和季节事件仍是派生通知，未接耐久投递确认。成功提交与通知之间退出可能漏通知；普通事件总线也不能证明订阅方已耐久处理。新事件使用原操作 UUID，但这里不宣称通知恰好一次。
- 创建/圈地准入仍粗粒度；旧无意图圈地需人工持独立证据核对。回执永久增长，同步全量文件/SQL 读写的规模和延迟需要测试与归档方案。每批上限 100,000 地块，文件上限 64 MiB；达到限制时拒绝新增而不删除重放证明。
- 改动生产源在空输出目录编译，并与最终 JAR 核对；这不是全仓干净 `verify`。最新 MySQL、完整插件组合及 Paper/Folia、生存生产和视觉验收仍待验。

按用户要求，本轮不启动服务器，不修改世界和玩家存档，生产 Folia 声明不扩大。
