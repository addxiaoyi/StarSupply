# 解散清理的领土与国库退役保护

这是第十五份补丁，在前十四份（最后为[国家分裂恢复](SPLIT-RECOVERY.md)）后应用 [starcore-retirement-recovery.patch](starcore-retirement-recovery.patch)。固定 Core 上游仍为 `f769e62799e769a18fe51305b545869a17f80cd1`。补丁随 StarSupply 开发分支提供，不直接推送 Core。

原解散清理只释放日志里的地块，并按当时国库余额普通提款，后续其他实例仍可能圈地、入账或退款。此补丁在两个实际权威中加入永久退役回执，接入现有解散清理。**这完成了完整解散协议的一部分；共享解散意图/终态及城市、外交、联盟、战争的持久退役尚未完成。**

## 领土协议

`TerritoryRetirementService.retireOwner(operationId, ownerId)` 在同一次文件提交或 SQL 事务中，移除该所有者当前全部领土，保留操作 UUID、所有者和实际释放数量。调用方必须先持久授权解散；接口没有恢复所有者或取消退役操作。同一所有者只能使用原 UUID 重放，换 UUID 会拒绝。

永久退役后，普通圈地、转移和新的批次/分裂转地不能把领土写回该所有者。旧批次和旧转移仍返回原回执，不重建后来已释放或转给其他人的领土。新批次结果 `OWNER_RETIRED` 保留为终态。其他所有者后来占领同一地块，不会被旧退役再次撤销。

领土快照在首次退役后使用 `batches.version=3`，保留原圈地和转移回执；没有退役时继续按原格式写入。SQL 增加 `starcore_territory_retirements`，与地块和既有回执共用版本、校验和和事务。存储提交校验退役回执只追加且释放数量匹配提交前权威；普通保存不能去掉退役记录。

## 国库协议

`TreasuryRetirementService.retireTreasury(operationId, nationId)` 读取权威，原子清空余额并保存操作 UUID、国家 ID 与原余额；零余额账户也永久关闭。重放返回原余额，不重新扣取当前余额。通过 `StarCoreApi.treasuryRetirementService()` 可查询该服务；调用方负责授权和原编号。

国库关闭后拒绝新的存款、收入、支出、转账和未发生的退款，保留历史资金回执供原编号查询与重放。已经完成的历史操作仍返回原结果；已退款的回执可查询，但没有新资金流入。关闭另一端的转账不会先扣付款方余额。停用后的旧服务引用不能继续写入。

退役历史写入 `receiptFormatVersion=2`，覆盖全快照校验；没有退役时保留 v1。文件保存改为同步确认、版本比较和严格读取，权威缺失或损坏时不静默退回旧备份。SQL 同一事务更新完整快照及独立退役表 `starcore_treasury_retirements`，两者必须一致；存储保护原余额、不可变退役记录和已关闭账户的资金回执。缺表、冲突和不明提交保留错误，恢复读取原编号。

国库后端固定；数据库中断不会切到文件，文件模式运行中也不自动切到新数据库。文件仍只支持单进程，多实例共享使用 SQL。升级时停止旧写入者，不能与旧协议混跑。首次文件到 SQL 迁移保留退役原余额/数量和历史回执；这不授权用旧备份覆盖已有 SQL 权威。

## 解散接线与边界

现有 `NationDisbandRecovery` 使用生产领土和国库实现的退役接口，以原解散事务 UUID 推进。清理中断后的重试可继续剩余步骤，日志生成后、退役前到达的合法领土和资金也纳入实际关闭结果。旧第三方服务仅实现旧接口时仍走遗留清理，不获得新退役保证。

共享国家目录中的解散意图/终态、全部外部服务的持久退役和跨实例普通国家修改约束仍需后续协议。城市和外交等清理现在仍为旧路径；这份补丁不把完整国家生命周期 P1 标成完成，也不自动修复已经无日志、无回执的历史解散。
