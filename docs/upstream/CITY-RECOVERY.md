# 城市持久退役与恢复（第十六份补丁）

在前十五份补丁后应用 `starcore-city-recovery.patch`。本补丁将城市接入现有国家解散清理，保留原编号退役结果，阻止迟到创建和旧城市对象复活。完整共享解散协议仍未完成；领土、国库和城市已有退役保护，外交、联盟、军事联盟及战争还需后续协议。

## 持久权威

- 文件模式将旧 `cities/<UUID>.json` 一次性导入 `cities/ledger.json`。快照包含版本、校验和、所有城市、永久删除标记及国家退役记录。`ledger.initialized` 在首次快照发布前持久写入；初始化中断、主文件或标记缺失、校验失败均拒绝继续，不自动退回备份或重新导入旧城市。
- 旧文件保留作为迁移证据，后续不参与权威读取。损坏、重复字段、文件名与城市 ID 不符、重名或居民跨城重复会阻止整批迁移，不跳过坏记录。初始化失败可能需要显式修复，不能仅删除标记后重新导入。
- 数据库开启时使用 `starcore_city_state` 和 `starcore_city_authority`；快照与版本/校验和在同一事务提交，包括初次文件导入。更新在共享版本条件下取得写入权，再验证旧快照和历史记录。单表/单行丢失、写入失败或数据库不可用均拒绝继续，不回退文件。后端选择在服务生命周期内固定。
- 文件模式只承诺单进程；同一进程的多服务实例以路径锁及旧内容比较协调。SQL 验证使用真实 SQLite；当前 MySQL 集成仍待验。完整权威被外部删除或恢复到旧备份时，必须使用独立证据进行运维恢复。

## 退役、普通修改与恢复

`CityRetirementService.retireNationCities(operationId, nationId)` 在一个提交内删除该国家当前所有城市、封存国家及记录排序后的原始城市 ID。零城市也会退役。相同编号重试返回原结果；同一国家换编号拒绝；历史退役记录不可修改或删除。调用者必须先持久化解散意图；退役不能取消或重新开启。

当前解散恢复优先使用该接口，因此处理的是城市权威中的当前归属，不再只依赖独立解散日志里过时的城市 ID。其他国家城市保留。第三方城市存储只实现旧接口时仍走原删除路径，没有新退役保证。

普通删除也永久封存城市 ID。存储返回的可变 `City` 对象记录其原始版本，之后的查询或重载不会把新版本借给旧对象。未知来源对象不能覆盖已有城市；被删除对象不能重新创建。服务的创建、修改、整批保存和删除还携带其已发布快照的版本，防止创建预检后跨实例变化被悄悄覆盖。`saveAll` 保留原来的批量更新语义，不删除输入中省略的其他城市，但整批校验和提交必须同时成功。

城市服务先确认存储再发布缓存和创建冷却；修改失败后重读实际权威，重建名称、国家及成员索引。提交后丢响应，仅在读回整个候选快照一致时视为成功；读回不可用则阻止后续访问，恢复可读后从实际状态继续。公开对象仍是可变 API；旧对象必须重新查询后再编辑，服务操作后也应重查当前状态。

模块注册 `CityRetirementService`，`StarCoreApi.cityRetirement()` 提供可选访问；停用后的服务拒绝操作，启用中途失败也清理已注册服务和命令。城市查询国家服务时不持有城市锁，避免与解散回调互相等待；回调重入修改被拒绝。邀请清理使用兼容调度器，但这不表示城市全部 GUI、权限、传送或跨区域路径已经完成 Folia 审计，实验 profile 没有扩大。

## 快照完整性

城市投票、选票、原始时间、等级上限、精确出生点坐标和朝向现在完整保存。JSON 严格拒绝重复字段、非 JSON 输入、非有限金额/坐标及无效身份，限制大小、嵌套和集合数量。世界不可用时拒绝实例化对应城市，保留原始出生点；存储层退役不需要加载世界。离线世界运维及整个城市模块不可加载时的解散安排仍待后续处理。
