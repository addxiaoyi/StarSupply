# 城市存取款与原编号恢复（第十七份补丁）

在前十六份补丁后应用 `starcore-city-money-recovery.patch`。原城市命令只修改城市余额，没有实际扣除或支付玩家资金；GUI 则分步操作两边余额，异常补偿不能确定款项是否已经提交。本补丁让命令、确认菜单和恢复入口共同使用 `CityMoneyService`，把原请求先保存，再按同一编号取得玩家资金回执，最后提交城市终态。

## 转账协议

请求固定操作 UUID、城市 UUID、玩家账户、存入/取出方向和精确金额。玩家回执使用同一个 UUID，来源包含城市 UUID。重复请求返回原结果；相同编号换城市、账户、方向或金额会拒绝。确认菜单绑定展示时的城市和原请求，之后换城、失去市长职位或重复点击不会把交易转向其他目标。

`PENDING` 意图与城市快照在同一次提交中保存。取款先从城市可用余额预留金额，存款先保留入账容量；同城只允许一笔待恢复交易，期间拒绝其他城市修改、成员变化、删除和国家退役。另一个城市仍可独立推进。准入以当前权威成员为准：居民可存款，市长可取款，命令和 GUI 还检查 `starcore.city.money` 权限。

之后查询或提交玩家原编号请求。玩家 `APPLIED` 回执才允许城市结算；余额不足、上限或扩展拒绝回执产生 `REJECTED` 终态，取款预留在同一提交中释放。拒绝同样占用原编号，之后资金增加或扩展规则变化不会让旧拒绝重新付款。玩家结果异常、回执冲突或城市写回失败保留原意图，不推测退款，也不换号重新付款。提交后丢响应只有读回完整候选权威一致时才直接认定成功。

终态保存完整玩家请求关联、状态、原余额、最终余额及时间；即使城市以后删除或退役，重放也只返回原终态。正常城市保存不能移除意图或修改终态，待恢复快照必须保留预留余额和其他城市字段。协调器调用玩家服务时不持有城市锁或生命周期锁；回调重入被拒绝，停用前已准入但尚未完成的操作可保留待恢复，旧服务引用不能继续准入或结算。

## 存储与精度

城市账本有资金历史后升级为格式 2；格式 1 继续可读。格式与资金字段、重复键、回执结构、金额守恒、城市预留、校验和及版本均严格检查。沿用文件标记和 SQL 事务版本协议；缺失或损坏权威不会退回旧文件或备份，也不会触发新的玩家付款。文件迁移到 SQL 保留待恢复交易和终态回执。迁移后必须停用旧文件写入者，不能同时运行不同后端或旧协议版本。

城市模型内部改为 `BigDecimal`，保留旧 `double` 方法，并新增精确余额访问。历史小数不擅自四舍五入，大额余额增减分币也保持精确。用户输入要求正数、最多两位小数，单笔不超过十亿；API 上限与玩家资金协议一致。超出协议上限的历史城市余额保留，但不能新建转账，须另行核对。

文件城市权威仍只支持单进程，文件玩家资金仍由一个权威服务负责；测试中的同进程多城市协调器共享该玩家权威。SQL 的独立城市与玩家实例使用共享版本拒绝旧快照，竞争失败后应按原编号重试。当前数据库行为验证使用 SQLite，最新 MySQL 集成尚未执行。

## 命令与生命周期

- `/city deposit <金额>`、`/city withdraw <金额>` 及菜单共用协议。相同玩家重复同城、同方向、同金额的待恢复命令会沿用原编号；已经终结后的新命令是新交易。
- `/city money list` 查看自己的待恢复交易；管理员查看全部，单次最多显示 50 笔。
- `/city money show <编号>` 查询，`/city money retry <编号>` 重试。本人或拥有 `starcore.city.money.admin` 的管理员可操作，授权控制台也可恢复。恢复只能推进已持久化的原交易，不能改金额或收款人。
- `starcore.city.money` 默认允许；`starcore.city.money.admin` 默认仅 OP。恢复已准入请求不重新解释当前玩法权限，不把撤销权限当成资金回滚。

模块在加载城市服务前尝试恢复所有待结交易；某笔玩家权威不可用时仍保留原记录，其他城市可继续恢复。存在 `PlayerMoneyService` 时注册城市资金服务，`StarCoreApi.cityMoney()` 提供可选访问；缺失时明确拒绝转账。停用和启用失败会注销并停止已发布引用。停用保存前读取最新城市权威，避免刚完成的资金结算被旧缓存覆盖。

本补丁关闭新城市存取款的资金链路，不包含整个城市玩法审计。城市邀请、其他书本输入与 GUI 会话、传送、权限矩阵和 Folia 线程归属仍需完成；临时输入物品在断线/停用时的恢复也需审计。旧无意图城市资金不能凭余额差自动判断或退款。待恢复交易目前只提供查询和推进，没有安全取消协议，不能通过删除记录解锁。

共享国家解散意图/终态、外交/联盟/军事联盟/战争持久退役仍为 P1。历史回执与同步全量快照仍需容量、归档和延迟工作；上限拒绝时保留记录，不能绕过上限丢弃重放证据。完整 Core 干净 `verify`、最新 MySQL 及 Paper/Folia、生存/客户端视觉验收仍待完成。按用户要求未启动服务器，世界和玩家存档未改动，生产 Folia 声明关闭。
