# 海军权限、持久化与维护修复

本补丁是第九份阶段检查点，不代表海军完整玩法已经闭环。它修复越权修改、已付款舰队的恢复、分钟补给和海战状态保存；真实陆军运输、港口自动补给、预算服务的中断一致性仍有代码缺口，详见 [代码闭环清单](../CODE-CLOSURE.md)。海军尚未加入实验 Folia 后勤 profile，生产 Folia 支持声明仍关闭。

## 应用

在原始 StarCore `f769e62799e769a18fe51305b545869a17f80cd1` 的独立工作树上，先依次应用后勤、玩家资金、税款、公共反馈、HUD、Clan、Religion 和 Faith 八份补丁，再应用 [starcore-navy-reliability.patch](starcore-navy-reliability.patch)。本补丁仅随 StarSupply 接续分支同步，没有推送 Core 或合并主分支。

```powershell
git apply --check C:\path\to\StarSupply\docs\upstream\starcore-navy-reliability.patch
git apply C:\path\to\StarSupply\docs\upstream\starcore-navy-reliability.patch
```

## 本次实现

- 命令同时检查基础权限、修改权限、国家领导者/海军管理员身份和舰队归属；完整 UUID 与短 ID 使用同样的授权规则，短 ID 有歧义时拒绝。攻击舰队和敌方目标分别校验。
- `navy/navies.dat` 升级为带校验和的 v2 文件，保存舰队、原始付款报价及战斗冷却。先保存付款意图，按原请求编号读取/提交国库回执，再保存并发布舰队。付款已提交而舰队保存失败时保留原编号恢复，不盲目退款或另起付款。
- 模块沿用原有直接国库支出，使用 `TreasuryService` 实例提供的耐久 `NationSpendingService` 接口；不切换到另一个全局预算权威。海军不消耗预拨军事预算池。旧构造函数也要求国库具备回执能力，缺失时拒绝启动。
- 所有舰队修改串行保存后发布，查询和事件返回独立副本；删除失败不丢内存对象，丢失写响应以实际文件精确读回确认。外部改写、损坏、仅剩恢复文件等状态拒绝覆盖。
- 每个运行分钟累积小时补给消耗的余量，余量跨重启保存；低补给只扣一次士气。海战伤害作用于对方，保存双方伤亡和对称五分钟冷却，检查外交关系、世界和距离。
- 分钟任务使用兼容异步调度；玩家移动触发只选择玩家所属国家的防守舰队，避免无关中立舰队被攻击。停用和启用失败取消任务、注销监听/命令/服务，旧订阅失效；事件线程标记随调用线程设置，通知失败不反转已提交结果。
- 修正中英文命令帮助的参数顺序，提供管理员 `/navy pending` 和 `/navy recover`。`embark`/`disembark` 提示明确表示只修改搭载记录，尚不转移实际军队。

显式 `createFleet(requestId, ...)`、`resupplyFleet(requestId, ...)` 支持原编号重放。已完成编号在舰队解散后仍保留，重放不会复活舰队或再次扣款。普通创建命令代表一次新购买；命令结果不明时先查列表和待恢复记录，不能把重复命令等同于同一业务编号重试。

## 自动化证据与边界

最终套件明细、测试数、源码/补丁/成品哈希、补丁重放及 StarSupply 实际兼容 JAR 测试见 [机器可读记录](../verification/workspace-navy-reliability-20261126.json)。改动生产源在空输出目录编译后打包；这仍不是当前 Core 全仓干净 `verify`。额外修正 `CompatSchedulerTest` 的弱引用模拟世界夹具，不修改调度器生产源码。

本次 Core 定向 718 项（其中海军 86 项）和实际成品下 StarSupply 177 项全部通过，0 失败、0 错误、0 跳过。22 文件补丁重放后的 3,557 个源码文件全部匹配；16 个海军生产源在空目录编译，25 个生成 class 与成品一致。最终 Core SHA-256 为 `7CBBF81FB402E3B888D097D7213DC15585B68FEE39A36640C978FC6EBDB55AB4`（19,713,101 字节）；StarSupply 生产 JAR 保持 `267DC0BB068714DFFB70D26C65B5AD4F09C7FF8E878489BD211D2A837C99C38C`。

直接国库与真实文件的测试覆盖准备/最终保存失败、已写入但响应丢失、损坏或冲突回执、重启恢复、并发限额、不可变读取、维护余量、战斗冷却、权限和启停。另有真实预算预拨池的正常路径与已保存回执重放测试，但它不证明预算中断恢复安全。

单独诊断已复现预算服务缺口：在国库扣款成功后、预算回执保存前用 `Error` 模拟进程中断，随后从实际文件重建两个权威。1000 余额支付 160 后为 840，原编号再试变为 680。该记录是已知缺陷的复现，不能计入通过测试或标为资金闭环；诊断只使用新建临时目录。

## 继续待办

1. `BudgetServiceImpl` 的预拨、国库补差和退款需要跨权威耐久意图；应按原编号恢复并保持预算分摊，不仅补异常退款。
2. 海军搭载记录接入真实军队的移出、移动、登陆、伤亡及返还，需要保存双方关联编号，避免复制或丢兵；`auto-supply-at-port` 仍无港口业务接线。
3. 全快照和终态付款记录随历史增长；需要有界存储、重放防护及容量/延迟验证。同步命令修改等待文件落盘，查询不等待写入。
4. 历史付款中引用的世界不可用或身份改变会拒绝加载，需明确离线世界维护/迁移策略。旧存档严格迁移，不静默丢弃损坏条目或回退到默认世界。
5. 当前事件为提交后的尽力通知，进程退出可能丢通知；一分钟维护只计算运行时周期，不追补停服时长。

没有启动 Paper/Folia，没有改动测试世界或玩家存档。当前完整插件组合、跨区域操作、六类生存资源链和客户端资源包继续保留实服待验。
