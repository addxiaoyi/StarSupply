# 国家分裂与领土转移回执恢复

这是第十四份补丁，在前十三份（最后为[圈地恢复](CLAIM-RECOVERY.md)）之后应用 [starcore-split-recovery.patch](starcore-split-recovery.patch)。固定 Core 上游仍为 `f769e62799e769a18fe51305b545869a17f80cd1`。补丁随 StarSupply 分支提供，不直接推送 Core。

原分裂使用独立文件日志：先转移领土，再保存国家目录，保存失败后反向转地。跨实例执行和迟到恢复缺少共享终态，无法凭当前领土归属证明原操作结果。新分裂把意图与国家目录共同保存，使用原编号领土回执继续完成；不再以反向转地补偿目录保存失败。

## 协议

1. `NationSplitService.Request` 保留操作 UUID、源国家、新创始人、新国家名、完整地块及源国家最低保留地块数。先在共享国家目录保存 `PREPARED`，同时固定目标国家 ID、创始人姓名与成立时间；保存确认前不转地。准入拒绝也保留终态，重放原 UUID 不重新准入。
2. 领土权威在一次文件快照或 SQL 事务中核实全部源归属和最低保留数量，再提交转移与不可变回执。结果为 `APPLIED`、`OWNER_CHANGED`、`REMAINING_LIMIT` 或 `CANCELLED`；重试读取原结果，不重新转移后来已撤销、转让或重占的地块。
3. `APPLIED` 后，把创始人移出源国家、添加固定目标国家，并与 `COMPLETED` 一起保存。最终保存失败保留原意图，恢复读取原领土回执继续提交，不反向转地。源国家经验与经验回执、创建历史、圈地历史和其他分裂历史均保留。
4. 取消先把共享意图保存为 `CANCEL_PENDING`，再向领土权威封存原转移编号。未提交的领土留下取消回执，拒绝迟到执行；领土已经提交则继续完成分裂。两种结果由领土原子提交决定，取消不会撤销已转移领土。
5. 终态重放只返回原回执。后来目标国家被删除或领土转移，旧请求不会复活国家、恢复成员或重新分配领土。

新接口可通过 `StarCoreApi.nationSplitService()` 获取，调用方负责权限并保存原 UUID。旧 `NationService.splitNation` 接入同一协议，只复用参数完全相同的**待恢复**请求；旧签名没有业务编号，不能据此承诺任意终态请求自动识别。管理恢复和生产启动恢复使用原编号。

## 管理入口

```text
/nation splitrecovery list
/nation splitrecovery show <完整操作 UUID>
/nation splitrecovery retry <完整操作 UUID>
/nation splitrecovery cancel <完整操作 UUID> confirm
```

控制台或操作者须具有 `starcore.admin`。取消需要显式 `confirm`，并说明已提交领土会继续完成分裂。停用的服务/命令引用不能继续写入，目录发布回调不能重入创建、圈地、分裂或普通目录修改。

## 存储和兼容边界

国家快照增加 `splitOperations` 和全快照校验；未产生分裂历史时保留原有编码。创建、圈地和普通保存均保留分裂历史。一个共享目录暂只允许一个待恢复创建、圈地或分裂。普通国家修改先核对上次已发布目录与最新权威，发现变化时加载新状态并要求调用方重试；不会给旧可变对象套用新存储版本再保存。

领土文件在有转移回执时升级到 `batches.version=2`；现有 v1 批次历史可直接读取并保留。SQL 增加 `starcore_territory_transfer_receipts`，与普通地块、圈地回执共用版本和校验和。转移回执只追加，不能删除或修改。文件仍只支持单进程；共享 SQL 支持多实例版本竞争。升级必须停止旧写入者，不支持旧协议混跑。

旧独立分裂日志仍由遗留恢复路径处理，保留“新目录不被旧快照覆盖”的检查；补丁不会为无原编号回执的旧分裂伪造证明。新分裂不创建或依赖这类日志。
