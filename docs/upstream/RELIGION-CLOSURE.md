# Religion 保存、圣地与 Folia 生命周期

第七份补丁 [starcore-religion-closure.patch](starcore-religion-closure.patch) 应用在 [Clan 补丁](CLAN-CLOSURE.md) 之后。原始 Core 基线仍是 `f769e62799e769a18fe51305b545869a17f80cd1`，前六份补丁顺序见 [上游说明](README.md)。这不是独立的 `module/faith` 国家信仰系统；后者在随后第八份 [Faith 补丁](FAITH-CLOSURE.md) 完成代码与定向验证。

原 Religion 的多个异步任务共用 SQLite 连接，选信仰和领取祝福在保存前就报告成功，删除圣地可被晚到的保存覆盖。加入事件只加载在线玩家，排行榜是占位内容；移动订阅未接线，中心区块索引也会漏掉大圣地边缘。关闭时未排空任务，世界未加载的圣地不能安全保存。

现在采用以下规则：

- 初始化完整读取、验证所有玩家与圣地，再发布服务。损坏记录使初始化失败，未加载世界仍保留名称和坐标。
- 专用单线程串行执行 SQLite 操作。选信仰、祝福、创建和删除圣地提交成功后才发布结果；一批脏数据在同一事务内保存，失败保留修改代次，后续重试不会清掉较新的修改。
- 提交响应不确定时冻结后续写入，重启后从数据库确定结果。调用者取消 future 不取消已接收的写入。
- 停用先停止接收操作、取消周期任务和实体反馈、注销移动订阅，再排空写入、冻结旧模型引用、保存和关闭数据库。初始化失败也能安全关闭。
- 祝福效果和异步命令消息进入玩家实体线程，执行时复核在线及服务状态。保留更强效果和同级无限时长效果；展示的祝福文案与实际原版药水效果一致。
- 圣地按世界名和完整范围覆盖的区块索引，包含负坐标边界；位置不再随调用者修改 Location 而漂移。信仰、贡献和圣力计算拒绝负增量，并避免整数溢出。
- `/religion stat` 提供真实前十名，包括离线玩家；按信仰、贡献降序和 UUID 排序。创建命令修正名称参数、半径错误提示和多余方块读取，选择信仰遵守对应权限。
- Religion 接入实验后勤 profile 的启动、命令与移动监听；其他未适配模块继续受限，生产描述符仍未声明 Folia 支持。

旧同步服务方法保留签名，等待耐久写入完成；命令使用新异步方法。低层模型修改合并异步保存，正常停用会最终刷新；在提交前进程突然退出仍可能损失最近的非命令修改。排行榜显示 UUID，不进行离线档案网络查询。个人祝福保留原规则，圣力 API 与教义禁忌没有新增消耗或惩罚玩法。
