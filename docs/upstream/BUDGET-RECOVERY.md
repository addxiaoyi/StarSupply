本补丁是第十份阶段检查点，修复预算预拨、国库补差和退款的跨保存中断。它不代表全部插件阶段完成；演习、真实运兵、伤兵和学说等缺口仍见[代码闭环清单](../CODE-CLOSURE.md)。

## 应用与兼容

在 StarCore `f769e62799e769a18fe51305b545869a17f80cd1` 上，依次应用后勤、玩家资金、税款、公共反馈、HUD、Clan、Religion、Faith 和海军九份补丁，再应用 [starcore-budget-recovery.patch](starcore-budget-recovery.patch)。仅随 StarSupply 接续分支同步，不推送 Core、不合并主分支。

```powershell

git apply C:\path\to\StarSupply\docs\upstream\starcore-budget-recovery.patch
```

预算文件升级为带 SHA-256 校验的 v3 快照，兼容读取 v1/v2；SQL 保留历史文件导入指纹。已有普通扣款但未留下回执的旧版本中断，无法凭当前余额自动判断或修复，须保留原账与独立证据核对。v1 已执行预算仍按原迁移约定视为已消耗，避免重复开放额度。

## 资金协议

- 先保存原始请求、国家、金额、分类、描述、预算池/国库分摊和时间，再调用国库耐久支出接口，最后保存预算回执或执行状态。预拨、支出、退款都沿同一协议；重启和每分钟任务使用原编号完成。
- 国库扣款按 `budget:v3:FUND:<账单 UUID>` 或 `budget:v3:SPEND:<请求 UUID>` 去重；退款继续使用旧版 `budget-spending-refund:<请求 UUID>` 信用回执键。真实国库接口实例提供扣款权威，避免递归调用全局预算服务。
- 完成前必须读取并逐项验证资金回执。成功返回值或当前余额都不能代替回执；缺失、冲突或已退款的扣款回执会保留待恢复状态，不能触发盲目补偿。
- 原始支出分类与描述原样保存，租金与租赁手续费不再被映射为同一种外部回执。旧回执缺少原始字段，仍沿用既有映射，不能补造历史信息。
- 分摊在准备时固定；跨月份恢复不会重新报价。纯预算支出不会再次扣国库，混合支出退款分别恢复预算额度和国库补差。
- 不足额且尚未准备时返回 `INSUFFICIENT_FUNDS`；准备后余额变化或资金权威暂不可用则保持原意图，并抛出可恢复失败。**当前同一预算权威只允许一个待恢复付款，新预算写入须先恢复它。** 不把未确认结果当作拒绝，避免另一个实例已扣款却被撤销预算意图。

## 存储与运维语义

文件使用原子替换和原始字节比较后保存，同一进程内的独立实例共享路径写入锁。损坏、重复属性、缺少主文件但留有恢复文件、非法引用或超额预算均拒绝继续，不自动回退旧备份。文件读写上限 64 MiB；文件模式仍须单进程持有，不能当作跨进程共享存储。

SQL 使用版本比较更新；竞争实例必须先赢得准备提交才能扣款。丢失提交响应时精确读回权威快照；无法确认或已出现其他新状态时，旧实例冻结，避免拿旧内存覆盖新提交。时间比较采用持久格式，兼容系统时钟纳秒与存档毫秒的差异。数据库故障不退回本地文件。

`BudgetServiceImpl.pendingPayments()` 可读取待恢复编号，`recoverPayments()` 可显式恢复；正常启用和每分钟任务也会恢复。日志 `BUDGET_RECOVERY_PENDING` 包含操作编号。缺钱时应恢复资金来源，存储暂不可用时应恢复原权威；不应改编号重试、删除意图或复制旧备份覆盖。结果不明且冻结的实例需在核对权威后重启。

当前没有预算专用管理员恢复命令，也没有跨实例安全撤销已准备付款的协议。旧月份剩余预拨池的结转/退回、全局待恢复对可用性的影响、有界回执归档和容量验证仍需后续收尾。停止服务取消任务并使旧引用失效；通知为提交后尽力记录，进程退出可能丢通知。
