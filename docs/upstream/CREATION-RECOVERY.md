# 建国与城邦创建付款恢复

本补丁为固定 Core 基线 `f769e62799e769a18fe51305b545869a17f80cd1` 的第十二份兼容补丁，在前十一份补丁（最后为 [演习恢复](EXERCISE-RECOVERY.md)）之后应用 `starcore-creation-recovery.patch`。只随 StarSupply 开发分支交付，不推送 Core 仓库。

旧实现先普通扣款，再写国家目录；失败恢复比较当前余额与旧余额，其他收支会干扰判断。新实现先将原请求、候选国家、原价、父国家和创建时间保存进国家目录，再按确定的原付款编号访问 `PlayerMoneyService`，最后把国家和创建终态放入同一次目录提交。目录文件与 SQL 都沿用版本检查，经验回执也保持在同一快照中。普通创建/城邦入口已使用此协议。

跨实例测试还复现了玩家 SQL 资金的旧快照覆盖普通收入：1000 余额在另一实例收入 100 后，创建扣 100 本应剩 1000，旧实现却剩 900。本补丁为普通账户批写和完整余额/回执快照引入共同 SQL 版本，在同一事务中比较并递增；过期写入会拒绝，资金服务刷新权威再恢复原操作。重新加载后，旧异步排队快照也不能借用新版本覆盖余额。SQL 权威读取不再使用旧的 30 秒缓存；已经发布的余额表为空时拒绝从旧文件重新导入。新增表 `starcore_player_balance_revision` 与资金数据一起备份；禁止新旧写入协议混跑。

## 原编号接口与恢复行为

`StarCoreApi.nationCreationService()` 或服务注册表提供 `NationCreationService`。调用者负责验证玩家身份和权限；跨重启调用者必须保存完整 `Request`，用同一 `operationId` 重试。接口新增是向后兼容的，既有 `NationService` 签名保留。

创建过程中的国家目录写入失败，不根据异常自动退款：意图会保留，启动或显式重试继续原操作。余额独立变化不会改变收费判断。结果已提交而调用方没有收到响应时，原编号返回既有结果；国家后来改名或解散也不会让旧编号重新创建或扣款。同一编号携带不同请求会被拒绝。

旧入口没有调用方提供的编号，只能自动复用匹配的待恢复创建；终态后的新调用仍是新请求。需要跨改名、转让、解散后精确重放的集成应使用新接口并保留原编号。

| 状态 | 行为 |
| --- | --- |
| `PREPARED` | 已存意图，沿原编号查询/完成扣款，再提交国家 |
| `CREATED` | 创建已提交，永久保留结果，重放不复活已解散国家 |
| `REJECTED` | 扣款被权威拒绝；充值后重放此编号仍返回原拒绝 |
| `REFUND_PENDING` | 取消或前提变化的退款决定已保存，沿原编号推进结算 |
| `REFUND_BLOCKED` | 退款被权威拒绝，例如余额达到上限；需排除原因后显式重试 |
| `REFUNDED` / `CANCELLED` | 取消结算完成；不会再发布候选国家 |

取消先持久化退款决定，再结清原扣款和退款。即使取消时尚未扣款，也需要让原扣款编号获得终态，避免已经开始执行的旧实例稍后扣款；因此可能出现一次扣款随后等额退款。若原扣款被拒绝则直接取消。付款权威对拒绝也会占用编号，所以余额上限导致的退款拒绝会保留 `REFUND_BLOCKED`，管理员重试先保存下一退款尝试，再使用该尝试的确定编号；同一尝试的未知结果不会换编号。

## 管理入口

以下命令可由拥有 `starcore.admin` 的玩家或控制台执行，只接受完整业务 UUID：

```text
/nation recovery list
/nation recovery show <UUID>
/nation recovery retry <UUID>
/nation recovery cancel <UUID>
/nation recovery cancel <UUID> confirm
```

`list` 显示待恢复创建；`show` 可以查询保留的终态。取消必须明确确认，且已完成的创建不会被这个命令解散。启动会重试未完成扣款/退款，但不会自动重新尝试已明确拒绝的退款。若存档自身不可读，写入会冻结，需先恢复权威存档并重载，不能用删记录解除阻塞。

## 国家生命周期保护

待恢复创建会阻止新的国家目录写入。创建、分裂、解散的旧日志存在时，常规目录修改及新创建会被阻止；扩展回调也不能重入创建或抹去意图。分裂快照保留创建历史，旧分裂恢复会先对照当前目录：若既不是日志中的前态也不是后态，就保留日志并拒绝覆盖后续改动。停用后的创建服务和命令引用拒绝继续操作。

旧创建日志没有资金回执，余额差不再作为退款或清除证据。若原国家确实已存在，可以清理已提交的旧日志；否则停止自动恢复并要求独立证据。该检查在注册国家监听器和命令之前执行。

## 验证与剩余工作

构建、测试数量、产物哈希和补丁重放结果见[机器可读验证记录](../verification/workspace-creation-recovery-20261126.json)。验证使用 192 MiB 堆，未启动 Paper/Folia，生产 Folia 声明保持关闭。

以下范围仍未完成：

- 圈地资金仍是旧普通扣款和进程内补偿；本补丁只在待恢复时阻止新的圈地入口，没有实现圈地的耐久业务协议。
- 旧分裂/解散日志的共享 SQL 协调和终态历史仍需重构。当前新增的入口检查与旧快照保护不能宣称所有国家生命周期的跨实例操作已经闭环。
- 新协议同一国家目录同时只允许一个待恢复创建。终态记录永久增长，规模、归档和同步写延迟待验证。
- 文件权威只支持同一服务器进程；多实例必须让国家目录与玩家资金分别共享同一 SQL 权威。本轮 SQLite 检查不替代最新 MySQL 集成验证。
- 旧无回执资金需要独立核对，严格快照引用的离线首都世界仍需维护策略。
- 当前 Core 全仓干净验证、完整可选插件组合和实服多区域验收继续保留待验。
